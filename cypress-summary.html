Cypress Cheat Sheet

סיכום מקצועי — כל מה שצריך לדעת על בדיקות אוטומטיות
v13+  ·  E2E & Component Testing
1

מהו Cypress?

Cypress הוא כלי בדיקות אוטומטיות לאפליקציות ווב. הוא פותח דפדפן אמיתי, מבצע פעולות (הקלדה, לחיצה, ניווט) ומוודא שהכל עובד כמצופה — במקום שתעשה את זה ידנית, שוב ושוב.
אנלוגיה: Cypress = רובוט QA שיושב מול הדפדפן ומבצע תסריטי בדיקה 24/7 — מהר יותר ובלי טעויות אנוש.
2

מבנה בדיקה

כל בדיקה בנויה משלוש שכבות: קבוצה → הכנה → בדיקה בודדת.
describe('Login Page Tests', () => {

    beforeEach(() => {                  // רץ לפני כל it
        cy.visit('/login');
    });

    it('should login successfully', () => {
        cy.get('#username').type('admin');    // 1. מצא + פעולה
        cy.get('#password').type('pass123');
        cy.get('button[type="submit"]').click();
        cy.url().should('include', '/dashboard'); // 2. בדיקה
    });
});

פקודהתיאור

cy.go('back')חזרה לדף הקודם בהיסטוריה
cy.reload()רענון הדף הנוכחי
4

סלקטורים — cy.get()

בחירת אלמנטים מה-DOM. התחביר זהה ל-CSS Selectors.
סלקטורדוגמההסבר
#idcy.get('#username')לפי ID
.classcy.get('.flash.success')לפי Class (אחד או יותר)
tagcy.get('h2')לפי סוג אלמנט HTML
[attr]cy.get('a[href="/logout"]')לפי Attribute
tag[attr]cy.get('button[type="submit"]')שילוב tag + attribute
[data-cy]cy.get('[data-cy="submit"]')⭐ Best Practice — יציב ולא נשבר
כלל זהב: תמיד העדיפו data-cy — הוא לא תלוי בעיצוב, לא ב-class ולא ב-text. האלמנט יכול להשתנות ויזואלית והבדיקה תמשיך לעבוד.
5

פעולות על אלמנטים

פקודהתיאור
.type('text')הקלדת טקסט לתוך שדה
.type('{enter}')מקש מיוחד — {tab} {esc} {backspace}
.click()לחיצה רגילה
.dblclick()לחיצה כפולה
.select('value')בחירה מ-dropdown (רשימה נפתחת)
.check() / .uncheck()סימון / ביטול checkbox
.clear()ניקוי תוכן שדה input
6

בדיקות (Assertions)

שני סוגים: .should() לאלמנטים ב-DOM, ו-expect() לערכים ומשתנים.

should — בדיקות על אלמנטים

בדיקהמשמעות
.should('be.visible')האלמנט נראה על המסך
.should('not.exist')האלמנט לא קיים ב-DOM
.should('contain', 'text')מכיל טקסט מסוים (חלקי)
.should('have.text', 'text')התאמת טקסט מדויקת
.should('have.value', 'val')ערך של שדה input
.should('have.length', 5)כמות אלמנטים שנמצאו
.should('have.class', 'active')לאלמנט יש class מסוים
.should('have.attr', 'href', '/x')לאלמנט יש attribute מסוים
.should('be.disabled')האלמנט מנוטרל (disabled)
.and('be.visible')שרשור — בדיקה נוספת באותה שורה

expect — בדיקות על ערכים (API / משתנים)

בדיקהמשמעות
expect(x).to.eq(200)שווה בדיוק
expect(x).to.be.an('array')בדיקת טיפוס — מערך
expect(x).to.have.length(100)אורך מערך
expect(x).to.have.property('id', 1)יש שדה עם ערך ספציפי
expect(x).to.include(obj)מכיל אובייקט
expect(x).to.be.lessThan(2000)קטן מ-

מתודהתחבירסטטוס הצלחה

POSTcy.request('POST', url, body)201
PUTcy.request('PUT', url, body)200

8

יירוט בקשות — cy.intercept()

מאפשר ליירט בקשות רשת, להחזיר תשובות מזויפות, ולחכות לסיום בקשות.

המתנה לבקשה

cy.intercept('GET', '/api/users').as('getUsers')
ואז: cy.wait('@getUsers')
מחכה שהבקשה תסתיים לפני שממשיכים.

Mock — תשובה מזויפת

cy.intercept('GET', '/api/users', { statusCode: 200, body: [...] })
מחזיר תשובה שאתה שולט בה — בלי שרת אמיתי.

סימולציית שגיאה

cy.intercept('GET', '/api/users', { statusCode: 500 })
בודק איך האפליקציה מתנהגת כשהשרת קורס.

Fixture — מקובץ JSON

cy.intercept('GET', '/api/users', { fixture: 'users.json' })
טוען תשובה מקובץ cypress/fixtures — נקי וקריא.

9

קבצי תמיכה

Fixtures

קבצי JSON עם נתוני בדיקה.
cy.fixture('users.json')
מאפשר להפריד data מ-logic.

Custom Commands

פקודות מותאמות שמונעות חזרתיות.
Cypress.Commands.add('login', ...)
שימוש: cy.login(email, pass)

e2e.js

קובץ הגדרות גלובלי — רץ לפני כל בדיקה.
מתאים ל: cy.clearCookies(), import commands, הגדרות משותפות.

Best Practices — 7 כללי זהב

1

השתמש ב-data-cy

סלקטורים שלא נשברים כשהעיצוב משתנה.

2

cy.wait('@req') ולא cy.wait(ms)

חכה לאירוע אמיתי, לא לשעון. יציב ומהיר יותר.

3

Login דרך API

אל תעבור UI בכל בדיקה — cy.request() מהיר פי 10.

4

דבר אחד לכל בדיקה

אם נשבר — תדע בדיוק מה. כל it() = בדיקה ממוקדת.

5

בדיקה עצמאית

כל בדיקה רצה לבד — לא תלויה בתוצאות של בדיקה אחרת.

6

Custom Commands

DRY — אל תחזור על אותו קוד. חלץ ל-commands.js.

7

אל תבדוק אתרים חיצוניים

רק את האפליקציה שלך. אתרים אחרים ישברו את הבדיקות.

13

CI/CD — GitHub Actions

git push → Clone Repo → Install Deps → Start App → Run Tests → ✅ Pass / ❌ Fail + Screenshots
